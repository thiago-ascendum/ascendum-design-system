How it works

Five steps, one command, no manual copy. Each step only reads the one before it.

1

Snapshot

The library is read into one neutral file: tokens, styles, components, and what every layer binds.

2

Tokens

tokens.json and tokens.css, light and dark, desktop and mobile, with their code names.

3

Checks

Rules that block, rules that warn, and questions that only the owner can answer.

4

Contract

AI-CONTRACT.md: what an AI tool may use, what it must never use, what to ignore in Figma.

5

Gate

Exit code 1 while a blocking check fails. The pipeline cannot publish past it.

Decisions live in one file

governance/governance.json holds what people decided: what is deprecated and why, the variant budget, which colour pairs must pass contrast, what an AI tool must never do. The checks and the contract are generated from it, so a decision is written once and enforced everywhere.

This page is the proof

Nothing here is typed by hand. Colours, radii and sizes come from build/tokens.css, the numbers from build/report.json. Press Dark mode above: the page changes because the tokens change.

Limits and what we recommend

What this does not do

  • LimitIt cannot see. Clipped shadows, cut-off text and weak composition pass every structural check. Those points stay with a person, on purpose.
  • LimitIt does not decide taste. How many button states, which neutrals stay: it measures and asks. The owner answers once, in the governance file.
  • LimitSeverity is a proposal. Which rules block and which warn is our suggestion. It is one line each to change.
  • LimitWe were wrong once, and the checking caught it. Our first pass reported two typefaces mixed across the file. Resolved through the text styles it is Barlow on layers and Inter on .
